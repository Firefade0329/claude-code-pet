## 1. 差异清单

### 中

#### D-1　"周末休息不会断"只在周末两天都不用时成立（中）　【实际运行 + 读代码】

- 文档：`README.md:77`（"周末休息不会断，周五用过、下周一接着用，连续天数继续；漏掉的是平常的工作日则从头开始"）；`CHANGELOG.md:55`（0.4.0："连续天数周末不断。周五用过、下周一接着用，连续天数继续"）。
- 代码：`register.tsx:885`，`continuesStreak = last === dayBefore(now) || (今天是周一 && last === 三天前)`。
- 差异：周一能接上的"上一次使用"只有周日（昨天）和周五（三天前）；**周六（两天前）接不上**。我在测试环境里设置存档、把时钟定在周一，三种情况各跑了一次：上次用周五 → 签到 7 点（连续继续）；上次用**周六 → 3 点（断了）**；上次用周日 → 7 点（继续）。此外，周五之后若在周六或周日用了一天（周五→周日也是两天间隔，`dayBefore` 对不上），连续也会断。我用模拟跑了几种使用方式：周一到周五用 → 最长连续 286 天（400 天内）；**周一到周五加周六 → 最长连续 6；周一到周五加周日 → 最长连续 6**；周一到周六 → 6。后三种人永远拿不到"一周陪伴"（7 天）、"满月之约"（30 天）、"百日相伴"（100 天）和依赖它们的"全部收集"。
- 建议：先决定意图：①"周末（周六、周日）可以不用，用了也不影响"——那么规则应该是"两次使用之间缺的日子都是周六或周日"就算连续；②"只放过周五到周一的整个周末"——那就保持现状，但 README 要写明"周末只要用了一天就会断"。我倾向①，伪代码见 `code-review-v0.5.0-2026-10-24.md` N-2。

#### D-2　"迁移只做一次"在多个对话同时首次启动时不成立（中）　【算术 + 读代码；并发窗口为推断】

- 文档：`README.md:79`（"升级前的存档会一次性把点数抬到……"）；`CHANGELOG.md:57`（"迁移只做一次（存档里记 `model: 2`）"）。
- 代码：`register.tsx:938-945`（`migrateModelLocked`）。
- 差异：见 N-1。顺序启动是幂等的（我实际跑了：旧 Lv.19 的 1500 点 → 1792，第二次 `session.start` 后仍是 1792）；但 `locked()` 只在一个对话里有效，几个对话同时首次启动时，后到的那个会把"已经抬过的点数"当作旧存档再抬一次（旧 Lv.9 以上会多升一级，再多一个对话再多一级）。
- 建议：文档层面，等代码修了再说；要在 CHANGELOG 里写明的话，写"迁移在几个对话同时首次启动时可能多抬一级"。
