# 英文化方案：做成可切换语言（预研）

> 只做预研，**没有改任何代码**。依据是 `hooks/register.tsx`（v0.3.2）、`pet.test.ts`，以及这个 Claude Code 版本（2.1.294）自带的插件开发文档和类型文件。
> 标记：**已确认** = 读了代码 / 文档，或我在临时目录里做了最小原型并跑过；**未验证** = 推断，或需要真实桌面端 / 终端才能确认。
> 相关文件：[strings-zh.md](strings-zh.md)（原文清单，约 390 条，标了行号）、[strings-en-draft.md](strings-en-draft.md)（英文草稿，含"Master"的备选方案）。

## 结论（先看这个）

1. **可行，而且插件接口里直接有现成的"语言选项"机制，不需要自己造设置存储。** 推荐方案：在 `plugin.json` 里声明一个 `userConfig` 字段 `language`（`zh` / `en`，默认 `zh`），模块在 `register(on, options)` 里读它。默认值保持 `zh`，所以老用户的体验完全不变。
2. **我做了一个最小原型来验证这条路（在临时目录里，没放进仓库）：** 清单里的 `userConfig` 通过了 `claude plugin validate`；不设置时拿到默认值 `zh`；`claude plugin test` 里用 `test(name, { options: { language: 'en' } }, body)` 能注入选项并拿到 `en`；选项值不在列出的 `options` 里（比如 `fr`）时回落到默认值（已确认）。
3. **要改的地方不多但很分散：** 台词表 261 句、成就 38 个（名称 + 描述）+ 7 个分组名、约 46 条按钮 / 面板 / 提示 / 命令文字，加上读取选项、单复数、分隔符、版式。
4. **最大的风险不是翻译，是版式：** 英文平均比中文宽约 1.7 倍（台词中位数 38 格对 22 格，最长 85 格对 48 格），桌面端按钮行最宽时从 61 格涨到 74 格，右侧信息栏从 48 格涨到 58 格，源码里 90 格的窄屏阈值需要重新定（见 §3）。这部分只能在真实桌面端和终端里肉眼确认，**未验证**。
5. **工作量估算 12–21 小时（约 2–3 个工作日），**不含找母语者校对的等待时间（见 §6）。这是估算，不是测量值。
6. **前提：** `hooks/register.tsx` 和 `plugin.json` 都是构建产物，源码和构建脚本在维护者本机、不在这个仓库里（CLAUDE.md）。下面说的"改哪里"是以 `register.tsx` 的行号表达的，维护者要对应到自己的模板；我没看到模板，所以对应关系**未验证**。

## 1. 语言设置从哪里读、怎么存

| 方案 | 做法 | 评价 |
|---|---|---|
| **A. 插件选项 `userConfig`（推荐）** | `plugin.json` 声明 `language` 字段；`register(on, options)` 读 `options.language` | 现成机制，有 `/config` 菜单里的选择器，存在 Claude Code 自己的设置里，不用自己写存储；可以用命令行 `claude plugin configure` 设置；测试里可以注入 |
| B. 读 Claude Code 自己的"语言"设置 | `$.settings.read()` 返回一个原样的设置对象（类型是 `Record<string, unknown>`），从里面找语言相关的键 | 键名和取值格式我**没有验证**（可能是自由文本，不一定是 `en` / `zh`），只适合以后做成 `auto` 选项的"猜测"，不适合当唯一来源 |
| C. 环境变量 | `$.env.get('PET_LANG')` | 要用户去改 `settings.json` 的 `env`，不如 A 友好；`$.env.get` 要求名字写成字符串字面量 |
| D. `/pet lang en` 命令 | 命令里调 `$.config.set(...)` 去改 A 的那个选项 | 类型里有 `$.config.set`、键名约定是 `<插件名>.<字段名>`（已确认存在）；能不能改自己的 `userConfig` 行**未验证**。可作为 A 的补充，不是替代 |

### 推荐：A，并且默认 `zh`

清单（这份我在原型里验证过它是合法的）：

```json
"userConfig": {
  "language": {
    "type": "string",
    "title": "Language",
    "description": "Language of the pet's text (zh = 简体中文, en = English)",
    "default": "zh",
    "options": ["zh", "en"]
  }
}
```

模块里（示意，不是要提交的代码）：

```ts
export const register: Register = (on, options) => {
  const LANG = options.language === 'en' ? 'en' : 'zh'   // 其它值一律当 zh
  ...
}
```

要点：

- **存在哪：** Claude Code 把选项存在 `settings.json` 的 `pluginConfigs.<插件名>.options` 里（文档写明，已确认）；`/config` 菜单里该字段是一行选择器；`claude plugin configure pet --values-stdin` 也能写（`--help` 里写了，已确认命令存在）。**插件自己不需要 `$.store` 也不需要 `$.state`，`types/index.d.ts` 不用改**——语言是配置，不是运行状态。
- **切换后怎么生效：** 文档写明"菜单里改了之后，模块会用新的 `options` 重新加载"，重新加载时 `register` 重跑、模块里的变量重置，`$.state` 和 `$.store` 里的值保留。所以模块里用一个普通的模块级变量 `LANG` 就够，不需要做"运行时热切换"。这一点我只读了文档，在真实会话里切换一次的表现**未验证**。
- **`plugin.json` 是构建脚本生成的**（CLAUDE.md），所以 `userConfig` 要加进维护者本机的构建脚本，不能手改仓库里的文件。
- **现在的 `register` 是 `on => {…}`（`register.tsx:893`），只收一个参数**，要改成 `(on, options) => {…}`。
- **以后加语言：** 只需要在 `options` 列表里加值、补一份表。

### 设计要点

- **带占位符的台词保持现在的 `{m}`、`{l}`、`{a}`、`{n}` 写法**（`say()` 已经负责替换），不用改机制；两种语言的占位符集合必须相同（草稿我已经用脚本核对过）。
- **按钮和面板里的变量用函数**（例如 `btnFocusCancel: (n) => \`Give up focus · ${n} min left\``），因为词序、单复数、分隔符各语言不一样。
- **单复数：** `panel.hidden`（"N more hidden achievements"）和 `panel.sum3`（"N days"）里的数字可能是 1。要么在函数里判断，要么用中立写法（"hidden achievements left: N"）。`streakLine` 只在 n ≥ 2 时出现，不用处理。
- **写死的数字：** "25 分钟"、"五分钟"、"一小时"等同时写在文字里和常量里（见 strings-zh.md §5），做英文化时顺手改成从常量生成，否则以后改常量会漏。
- **文字和代码放在哪：** 两种做法。① 全放进 `register.tsx` 里（构建产物变大，约 +390 条）；② 拆到 `hooks/` 里的单独文件，由 `register.tsx` 用 `import` 引用（文档写明插件里的其它文件可以 `import`，已确认）。②便于测试和以后加语言，但要看维护者的构建脚本是否支持输出多个文件，**未验证**。
- **图片里有没有字：** 我没有检查 `assets/` 里 21 张图是否带文字（从截图上看没有），**未验证**。

## 3. 版式影响（我量化过）

用显示宽度估算（中文字符算 2 格、英文字符算 1 格；这是估算，不是真实像素）：

| 项目 | 中文 | 英文草稿 |
|---|---|---|
| 台词宽度：中位数 / 第 90 百分位 / 最大 | 22 / 32 / 48 格 | 38 / 57 / 85 格 |
| 台词宽度 ≥ 60 格的句数（共 261 句） | 0 | 16 |
| 按钮行：常态 | 34 格 | 34 格 |
| 按钮行：压缩上下文按钮出现时 | 46 格 | 51 格 |
| 按钮行：专注进行中 | 41 格 | 49 格 |
| 按钮行：最宽的情形（专注中 + 压缩 + 知道啦） | 61 格 | 74 格 |
| 右侧信息栏（两栏合计，含间距） | 约 48 格 | 约 58 格 |

结论和需要注意的地方：

- **桌面端按钮行不换行**（`:1161`：`flexWrap` 在桌面端是 `nowrap`），英文最宽时多出 13 格，可能溢出。要么在英文里再缩短（例如 "Give up focus · 25 min left" → "Stop · 25 min left"），要么让桌面端在英文下允许换行。
- **窄屏阈值 `NARROW_COLS = 90`**（`:83`，源码注释写明"a guess"）：英文的右栏大约宽 10 格，阈值应该跟着调高，具体值要在真实窗口里试。
- **台词用 `wrap="truncate"`，放不下会被截断**（`:1229`）。有 16 句英文 ≥ 60 格，最长的是阶段 2 的休息提醒（85 格）。要决定是缩短这些句子，还是允许两行。
- 终端版只有一行文字（`:1212`），英文更容易被截断，同样要看。
- 以上都**只能在真实的桌面端和终端里肉眼确认，我没有验证**。

## 4. 测试怎么覆盖

现状：`pet.test.ts` 共 43 个测试，大量用中文正则找界面文字（79 行含中文）。**策略：默认语言保持 `zh`，现有 43 个测试原样运行，作为"没有改坏中文"的回归门槛；新增一个单独的测试文件**（`claude plugin test` 会运行目录下所有 `*.test.ts`，`--help` 里写明，已确认），不去把现有测试全部参数化。

| 新增测试 | 做法 | 抓什么 |
|---|---|---|
| 1. 选项回落 | `{ options: { language: 'fr' } }` 应当表现为中文；不传选项也是中文 | 默认值和非法值（原型里已验证这个机制本身可用） |
| 2. 英文下没有中文字符 | `{ options: { language: 'en' } }`，依次触发 `/pet long / rest / ach / hello / focus / break / compact / warn / level 7 / start / cancel`，再点各个按钮和面板，对所有 `Text` 和 `Button` 的内容检查没有 `[㐀-鿿　-〿＀-￯]` | 漏翻的字符串 |
| 3. 三个阶段 × 两种语言 | 用 `engine($, on, { affection: N })` 设置存档，N 取 0、201（Lv.7）、809（Lv.14）（现有测试就是这样设置的），每个阶段跑一遍上面的演示 | 阶段 0 / 1 / 2 的表都有、都对 |
| 4. 数据对等 | 若语言表放在单独的模块里（§2 的做法②），直接 import 后逐类别、逐阶段比较句数，逐句比较占位符集合，逐成就检查 `id` 都有名称和描述 | 少一句、占位符写错 |
| 5. 英文冒烟 | 英文下：按钮文字（`Pat head`、`Focus 25 min`）、`成就` → `Achievements 0/38`、`/pet version` 返回 `Pet v…`、窄窗口时右栏消失 | 基本流程和新的窄屏阈值 |
| 6. 单复数 | 构造隐藏成就剩 1 个、连续 1 天的情形 | "1 more hidden achievements" 一类的错 |

注意事项：

- **不要把演示 × 阶段 × 语言放进同一个测试里循环**：现有的 `streak` 测试就因为单个测试太慢（推进 24 小时）超过默认 5 秒超时而失败（`code-review.md` A-12），新增测试请拆成多个小测试，或像那条一样加 `{ timeoutMs: … }`（注意是 `timeoutMs`，已确认）。
- 如果语言表放在 `register.tsx` 里、测试没法直接 import，第 4 项就只能通过界面间接做（用演示命令 + 阶段矩阵覆盖大部分类别），覆盖面会小一些。
- 视觉版式（§3）**没法自动测试**，要写进手动检查清单：桌面端宽窗口 / 窄窗口、专注中、休息中、压缩按钮出现时、成就面板展开时、终端版；每种在英文下各看一遍。
